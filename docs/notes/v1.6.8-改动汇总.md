# v1.6.8 改动汇总（本地已部署，未推 GitHub）

## 一、反代用量按版本分开

**你看到的**：国际版 API 反代页的「反代用量」里出现 `账号-国内-1`、`账号-国内-6`、`账号-国内-3` 这些**国内号**。

**根因**：`proxy-usage.json` **根本没有版本维度**。
`UsageMeta` 只有 `uid / nickname / model / stream`，两版混在同一个 `total` / `byAccount` / `byModel` / `recent` 里；
前端 `getProxyUsage()` 也不带参数 —— 两个页面读的是同一份混合数据。

**改法**：

- 存储改成按版本分桶：
  ```json
  { "updatedAt": 0,
    "byEdition": {
      "domestic":      { "total": {…}, "byAccount": {…}, "byModel": {…}, "recent": […] },
      "international": { "total": {…}, "byAccount": {…}, "byModel": {…}, "recent": […] }
    } }
  ```
- **旧数据自动迁移**（读的时候就地拆，下次落盘固化）：
  - `byAccount` 的**键就是 uid**、`recent` 每条也带 `uid` ⇒ 按账号档位**精确归位**；
  - 每档 `total` **不照抄旧的混合值**，而是由该档 `byAccount` **重新求和**（比估算准）；
  - ⚠️ `byModel` 不含账号信息、**拆不开** ⇒ 只能丢弃（纯展示项，之后重新累积）；
  - 已是新格式就原样返回（幂等）；空/损坏文件返回空结构。
- 「清空」按钮改为**只清本页这一版**，提示文案同步改成「本页的用量统计已清空」。
- 反代自身 HTTP 服务的 `/usage-stats` 也只返回**本入口那一版**。
- 前端缓存键含参数（`readCacheKey(cmd, args)`）⇒ 两个页面不会串数据。

> 迁移后：国际号（`账号-国际-1` / `账号-国际-2` / `账号-国际-3` / `账号-国际-4`）留在国际页；
> 国内号全部回到国内页。**`byModel` 的历史会从零开始**（拆不开，唯一的取舍）。

## 二、统计卡片数字撑破格子

`2,090,910,241` / `6,231.770` 在四列布局里装不下（每格内宽一百多像素，`text-xl` 放不下 13 位数）。

## 三、统计卡片字号不统一

上一版改成「按各卡片自己数字长度分别定档」，结果一排里**一张大一张小**（你的截图就是）。

## 四、进页面要手点「刷新」用量才更新

**根因在 SWR 读缓存**。`get_proxy_usage` 原来在 `CACHEABLE_READS` 里，而 `call()` 的逻辑是：

```ts
if (!forceFresh && hit && age <= FRESH_MS) return hit.value;   // 60 秒内直接返回旧值，不刷新
```

⇒ 进页面拿到的是**最多 60 秒前的**用量，而且**不会更新组件**，只能手点刷新。

修法：把 `get_proxy_usage` 从 `CACHEABLE_READS` 移到 **`LIVE_READS`**（既不缓存、也不清缓存）。
用量每个请求都在变，本就不该缓存；放 `LIVE_READS` 又不会把同一次挂载里其它缓存白刷掉。

> 顺带确认：切页用的是路由（`/api-proxy/domestic`、`/api-proxy/international`），
> 路由切换会重新挂载组件、`load()` 本来就会跑 —— 所以问题纯粹出在缓存上。

## 五、🔴「整池罢工」的真正根因（今晚踩了两次）

你看到的 `503 国际版的账号当前都不可用（冷却中，或需要重新登录）` —— 查下来
**4 个国际号全部被标 `needs_relogin`**，原因统一是：

```
刷新失败(code=-1): error sending request for url (https://www.workbuddy.ai/v2/plugin/auth/token/refresh)
```

`refresh.rs` 原来这样写：

```rust
let resp = http_request(&url, "POST", ...).await;   // 网络失败 → {"code": -1}
let code = resp.get("code").and_then(Value::as_i64).unwrap_or(-1);
if code != 0 && code != 200 {
    account["needs_relogin"] = json!(true);         // ← 网络错误也照标
}
```

**它把「网络抖了一下」和「refresh token 失效」当成同一件事。** `http_request` 对网络错误
一律返回 `{"code": -1}`，于是：**网络一抖 → 号被永久踢出反代池（`eligible_accounts` 会跳过）
→ 池空 → 503**。

今晚这个坑踩了两次：**国内版 19:18 / 20:09、国际版 21:53 / 22:05**。两次你看到的都是
「账号怎么都废了」，其实全是网络瞬时失败被当成永久失效。

**修法**：在 `code` 判断之前先处理 `code == -1`：

1. **先重试一次**（600ms 间隔，网络抖动多为瞬时）；
2. 仍失败就**原样返回、不落盘、不标 `needs_relogin`** —— 旧的 access token 可能还有效，
   后续请求会再试；瞬时失败交给反代的失败冷却去兜；
3. **只有上游真的拒绝**（401 / token 失效等）才标 `needs_relogin`。

## 六、切页不重新拉数据 → 必须手点「刷新」

**先排除误判**：`proxy-usage.json` 里 `byEdition` 已就位，直接查反代自带端点也是对的 ——

**真因是 React 复用实例。** `App.tsx` 里：

```tsx
<Route path="/api-proxy/domestic"      element={<ApiProxyPage edition="domestic" />} />
<Route path="/api-proxy/international" element={<ApiProxyPage edition="international" />} />
```

国内版/国际版是**同一个组件**、只换 `edition` prop。react-router 切换路由时，React 在
**同类型同位置**会**复用同一个实例**（不是卸载重建）⇒ 页面里：

```tsx
useEffect(() => { void load(); }, []);   // 空依赖 → 切换时不会重跑
```

于是切到国际版，看到的还是国内版那份数据，必须手点「刷新」。**你的症状完全对上。**

**修法**：依赖数组带上 `edition` —— `}, [edition]);`。

> 全仓扫过，只有这一对路由是「同组件多路由」，其它路由组件不同、切换会正常重挂载，不用改。

## 现在的 503 是另一回事：传输层失败也在冻号

你 23:22 / 23:48 两次是：

```
503 {"message":"国际版的账号当前都不可用（冷却中，或需要重新登录）"}
```

4 个国际号 `needs_relogin` 全是 `None` —— 不是标记问题。503 的产生条件是
「池子里**有**该版本的号，但**全在冷却**」。查下来是这段：

```rust
let r = match req.json(&upstream_body).send().await {
    Ok(r) => r,
    Err(e) => {
        st.pool.mark_failed(&uid);        // ← 网络失败也冻号 120 秒
        return (StatusCode::BAD_GATEWAY, e.to_string()).into_response();
    }
};
```

国际版只有 **3 个号**（白名单里另外两个是国内号，按归属排除）。`www.workbuddy.ai`
的直连今晚一直在抖（实测 200 与瞬间失败交替），抖几下就把 3 个号全冻 120 秒
→ 503「账号都不可用（冷却中）」→ 过两分钟恢复 → 再抖再冻。

**这就是「一会报错停下来、一会又能用」的机制**，和 `refresh.rs` 里 `code=-1` 那个坑同源。

## 修复：统一原则 —— 只有账号级失败才冻号

| 失败类型 | 之前 | 现在 |
|---|---|---|
| `send()` 传输失败（DNS / 超时 / 连不上） | 冻号 120s | **不冻号**，只重试 1 次（400ms），仍失败如实回 502 |
| 上游 **5xx**（502/503/504…） | 冻号 120s | **不冻号**，只打日志 |
| 上游 **4xx**（鉴权 / 额度 / 11128） | 冻号 120s | 仍冻（这类确实是账号级问题） |
| token 刷新网络错误（`code=-1`） | 标 `needs_relogin` | **不标**，重试 1 次后原样返回 |
