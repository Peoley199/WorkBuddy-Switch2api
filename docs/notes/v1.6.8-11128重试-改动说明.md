# wb-switch v1.6.8 —— 11128「渠道校验」自动重试

> 只改了 `crates/wb-switch-core/src/modules/proxy.rs` 一个文件（其余 10 个是版本号）。
> 国内版 7863 与国际版 7864 **共用这一份**，一处改动两个入口同时生效。

## 为什么要改

DSH 走国内版 7863 时偶发：

```
400 {"code":11128,"msg":"Illegal API invocation from an unapproved channel",
     "displayMsg":{"zh":"请求被拦截，请重新发送"}}
```

**实测证明它与请求内容无关**（用你那次会话的真实 payload 逐一对照）：

| 实验 | 结果 |
|---|---|
| 直连上游，同 payload × 12（假 model 名，零消耗） | 12/12 过渠道校验 |
| 直连上游，同 payload × 6（真 model，短/全量各 3） | 6/6 = 200 |
| 经反代 7863，全量 payload + 真 model | 200 通过 |
| payload 里 `gitStatus:` 出现次数 | **0**（不是环境注入块那条路） |
| 反代出站头 vs 手工直连头 | 逐字段一致（不是头伪装不够） |

⇒ 这是上游**间歇性软拦截**，它自己的文案就是在邀请重发。

## 原来的两个问题

1. **单发不重试** —— 一次 `send()` 定生死。
2. **上游任何非 2xx 都冷却账号 120 秒**（`COOLDOWN`）。

后果：11128 打来一次冻一个好号，DSH 又提示「请重新发送」→ 你再发 → 又冻一个。
你只有 **6 个可用国内号**，几轮就把整池冻死 2 分钟（探针时已复现 `503 账号冷却中`）。
而**号本身是好的** —— 冻它纯属误判。

## 改了什么

1. 新增 `is_channel_block(text)`：认 `11128` / `unapproved channel`
   （子串匹配 —— 上游把内层 JSON 当字符串塞进 `message`，取不到结构化字段）。
2. 发送改为 `loop`：命中渠道校验 → **重试最多 2 次**（300 / 600ms 递增退避）；
   每次**重新调 `chat_headers`** 生成会话头族（id 是现算的，避免同一 request id
   被上游当成重复包直接判掉）。
3. **只有重试仍被拦才 `mark_failed`** —— 不再一次误判就冻号，
   并在重试/放弃时打 `[反代]` 日志。

## 验证情况

- ✅ 单测：`cargo test -p wb-switch-core --lib` = **265 passed / 0 failed**，
  含新增 `detects_channel_block_from_upstream_body`（真实响应体命中；11102 / 11101 不误伤）。
- ✅ `RUSTFLAGS="-D warnings"` 干净（对齐 CI 门槛）。
- ✅ exe 核验：版本 `1.6.8`、前端已嵌入、含 `unapproved channel` 与 `渠道校验拦下` 字面量。
- ✅ 已部署 `<安装目录>//workbuddy-switch//`，与编译产物 md5 逐字节一致
  （旧版备份 `wb-switch-rust.exe.old-1011-205647`）。
- ❌ **未能做端到端重试演示**：试了四种摆法都**复现不出 11128**（全部 11102），
  也就没法构造"确定会触发重试"的请求。这条只能靠你实际使用观察。
  ⚠️ 顺带发现：记忆里那条 `gitStatus` 触发配方**现在已失效**。

1. 启动 wb-switch（我为了部署关掉了它，现在没在跑），确认界面显示 **1.6.8**

3. 若再撞 11128，反代会自动重试，**你应该感觉不到**；账号池也不会被冻
