## 1. 你反馈的问题

> 国际版会话记录怎么没有共享！我现在又添加了个账号

**结论：是我的判断错了。** 上一轮我照抄上游 `changexbc/workbuddy-switch` 的能力探测结论，
写死了"国际版不支持会话复制/共享"，所以你切到新加的国际版账号
（`账号-国际-2` / `uid-xxxxxx`）后，那 9 个会话还是挂在旧账号（`账号-国际-1` / `uid-yyyyyy`）名下，
客户端按 `user_id` 过滤就直接看不到了。

## 2. 两条硬证据（证明国际版完全支持）

**① 磁盘上三件套齐全**

```
~/.workbuddy-ai/workbuddy.db                  ← sessions 表，9 行
~/.workbuddy-ai/projects/{工作区}/{cid}.jsonl  ← 会话正文，9 个
~/.workbuddy-ai/edge-sync-mapping-v3.db       ← 云端归属映射
```

**② 客户端源码里就写着共享语义**（`<安装目录>\WorkBuddyAI\resources\app.asar`）

```sql
-- 国际版原文
FROM sessions WHERE deleted_at IS NULL
  AND (user_id = ? OR user_id = '')

-- 国内版注释原文
-- 「重建时 userId 设为空字符串，上层 getSessions 通过
--   user_id IS NULL OR user_id = '' 条件保证这些记录对当前用户可见」
```

两个版本语义完全一致 ⇒ 共享机制通用。
（顺带核过：国内版 `app.asar` 与旁边的 `app.asar.wbshare-backup` **sha256 完全相同**，
说明没被任何工具改过，`user_id = ''` 是官方机制而非补丁。）

### 顺带修掉两个真 bug（国内版同样受影响）

1. **云端映射从未写成功**：代码硬编码 `edge-sync-mapping-v2.db`，
   而实际的库叫 `edge-sync-mapping.db`（无版本后缀）。
   `register_edge_sync_mapping` 一直静默返回 `false`。现已改为目录探测。
2. **我们的会话列表与客户端不一致**：原来只按 `user_id = ?1` 查，
   而客户端是 `user_id = ? OR user_id = '' OR user_id IS NULL`。
   ⇒ 走完「共享会话」后，我们界面显示"当前账号暂无会话"，客户端里却看得到。

## 4. 已经对你的数据做了什么

把国际版现有 **8 个** `uid-yyyyyy` 的会话共享（`user_id` 置空）：

| 项 | 值 |
|---|---|
| 操作前 | `user_id` 分布：`uid-yyyyyy-…` × 8 |
| 操作后 | `user_id` 分布：`''` × 8 |
| 备份 | `C:\Users\<用户名>\.wb-switch\backups\sessions\20260924T131026\`（`workbuddy.db` + `-wal` + `-shm`） |
| 前置条件 | 操作时已确认 `WorkBuddyAI.exe` 未运行 |

**复核结果**：`账号-国际-1` 与 `账号-国际-2` 两个账号**都可见这 8 个会话**，8 个正文 jsonl 齐全：

```

```

## 6. 你接下来怎么用

1. 打开客户端点「切换」到任意国际版账号 → 弹窗里现在会**默认开启「共享全部会话」**
2. 也可以勾选「复制会话到目标账号」，把指定会话以新 id 复制一份给目标账号
3. 国内版行为不变（它本来就是这么工作的）

> 提醒：切换会关闭并重启对应版本的客户端（国际版是 `WorkBuddyAI.exe`）。
> 首次测试建议先手动完全退出 WorkBuddyAI。
